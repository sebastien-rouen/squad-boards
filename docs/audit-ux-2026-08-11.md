# Audit UX/UI — 2026-08-11

> Audit complet (navigation, workflows SM, design system, accessibilité, performance perçue).
> Propositions visualisées dans [static/mockups/ux-optimisations.html](../static/mockups/ux-optimisations.html) — **à valider avant implémentation**.

## Verdict global

Le socle est sain (tokens bien conçus, dark mode réel, store global cohérent, command palette riche) mais **les migrations s'arrêtent en chemin** : la bonne solution existe presque toujours déjà dans le code (`tokens.css`, `tooltip.js`, `confirmDanger()`, `--*-text`, `:focus-visible`, skeletons) sans avoir été généralisée. La dette est donc surtout **mécanique et à faible risque**.

## 🟡 P3 — Modérées

- Aucune modale « ? Raccourcis » ni lien vers les guides `docs/guide-*.md` depuis l'UI ; fonctions puissantes (templates Slack, favoris, mode TV, présentation PI) sans affordance.
- Empty states absents de 7 vues majeures (dashboard, sprint, backlog, health, atlas, agenda, settings) ; écran vide au premier chargement (aucun skeleton avant `renderView`).
- 21 `confirm()` natifs (dont « Tout supprimer ? » `settings.js:4013`) alors que `confirmDanger()` existe ; 583 `title=` vs 19 `data-tooltip` (migration tooltip abandonnée).
- Adoption tokens ~40 % : 861 font-size littéraux (519 < 12 px, min 6,5 px), z-index jusqu'à 11500 hors échelle, `.btn-ghost` écrasé globalement par `poker.css:117`, `.card` écrasé par `reports-epic.css:321`, 138 `!important`.
- 17 breakpoints distincts sans échelle partagée ; cibles tactiles ~20 px (recommandé 44 px).
- Settings dans le groupe « Pilotage » avec raccourci `8` (administration au même niveau que le pilotage quotidien).
- Anomalies Health dupliquées health.js/alert_modal.js (footgun documenté, toujours présent).

## Plan proposé (à arbitrer via le mockup)

> ✅ **Livré en 3.139.0 (2026-08-12)** — lots 1 à 4 complets + lot 5 partiel (modale « ? », empty state
> Backlog, confirmDanger). Reste en fond de tâche : migration couleurs→tokens (dont séries charts.js —
> l'infra thème `css()`/`redrawAllCharts` existe déjà), `title=`→tooltip.js, empty states des autres
> vues, refonte Dashboard direction F (cf BACKLOG).

- **Lot 1 — Quick wins** (~1 j) : piOffset persistant, bouton Daily en topbar, garde `isContentEditable` sur `N`, aria-live toasts, resync Ctrl+K/menu + labels unifiés, `--*-text` sur badges + taille 11px, persistance boardMode/filtres sprint + reset filtres backlog au changement d'équipe.
- **Lot 2 — Accessibilité cœur** (~2 j) : cartes focusables + keydown (Entrée=ouvrir, flèches+modif=déplacer), focus trap mutualisé pour les 4 modales, `role="dialog"` partout, restauration focus, aria-current sidebar.
- **Lot 3 — Performance** (~1 j) : lazy loading des vues (`VIEW_RENDERERS` dynamiques), skeleton au premier chargement, remplacement des ~20 `await import('../utils.js')` inutiles.
- **Lot 4 — Mobile** (~1-2 j) : PI + Scrum/Kanban dans le kebab, fix min-width bannière agenda, cibles tactiles, breakpoints unifiés (640/1024/1200).
- **Lot 5 — Fond de tâche** : migration tokens/couleurs (commencer par charts.js pour le dark mode), confirmDanger, tooltips, empty states, modale « ? », refonte Dashboard direction F (déjà arbitrée au BACKLOG).
